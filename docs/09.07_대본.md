# 09.07 7차시 발표 대본

> 총 예상 시간: 약 3분 30초
> 말하기 약 2분 20초 + 영상 1분 10초
> 발표 화면: Overview → Research → Pipelines → 시연 영상 → Paper Execution

## 1. 문제와 이번에 완성한 부분 — 약 25초

**화면:** `먼저 보는 결론`과 Archify 구성도

안녕하세요. 기존 파이프라인은 경제 발표와 시장 데이터를 수집하고 PostgreSQL에 저장했지만, 사용자가 최종 결과를 읽는 장면이 부족했습니다.

이번에는 저장된 데이터를 다시 분석하고 FastAPI와 `시장 이벤트 분석 대시보드`에서 조회하도록 연결했습니다. 즉, 수집·처리·저장·분석·읽기를 하나의 흐름으로 완성했습니다. 연구 신호의 자동 주문은 `RESEARCH_ONLY / NO_TRADE`로 잠겨 있지만, 사용자가 직접 승인하는 Alpaca Paper 수동 모의주문은 별도 기능으로 구현했습니다.

## 2. 데이터와 구조 — 약 25초

**화면:** `1. 문제와 실제 데이터` 표와 구성도

분석 범위는 CPI, 고용보고서, PCE, FOMC 총 202회와 10종목을 조합한 2,020개입니다. 이벤트별 선택 합계로 1분봉 308,512개, 파생 3분봉 112,593개, 5분봉 70,090개, 경제 환경 2,020행과 영향 분석 8,080행을 만들었습니다.

3분봉과 5분봉은 1분봉에서 만든 파생 데이터이므로 이 숫자를 모두 더해 하나의 원본 건수라고 말하지 않습니다. 가격이 없는 분도 임의로 채우지 않고 실제 관측 개수와 품질 상태를 보존합니다.

## 3. 시연 영상 — 1분 10초

**화면:** `docs/evidence/session7-demo/session7-submission-demo.mp4`

**실행 원본:** `docs/evidence/session7-demo/session7-actual-e2e.txt`

### 영상 시작 전 — 약 10초

지금부터 저장된 CPI 2026년 7월 발표와 NVDA 한 종목을 입력으로 사용한 사전 시연을 보여드리겠습니다. 외부 API, Kafka 대용량 재생과 실제 주문은 호출하지 않습니다.

### 영상을 재생하며 말할 내용

- **0~21초:** 위쪽은 Airflow 기반 시장·경제 데이터 경로이고, 아래쪽은 Kafka와 Spark를 이용한 원시 체결 처리 경로입니다. 두 경로의 결과는 PostgreSQL에 저장되고 분석·서빙 계층으로 연결됩니다.
- **21~34초:** 이 부분은 실제 리허설 명령의 결과를 정리한 캡처입니다. 한 조합을 입력해 영향 결과 4행과 전략 결과 1행을 Upsert했고, 중복은 0건입니다. 이어 같은 서빙 계층으로 1분·3분·5분봉을 다시 읽었습니다.
- **34~51초:** 이제 `시장 이벤트 분석 대시보드`가 PostgreSQL에 저장된 CPI·NVDA 결과를 실제로 조회하는 화면입니다.
- **51~70초:** 발표 전후 1분봉 180개, 네 구간의 영향 결과와 당시 경제 환경을 확인합니다. `LONG`은 과거 데이터의 연구 신호라 자동 주문으로 연결되지 않습니다.

### 영상 종료 후 — 약 10초

이 실행은 0.43초가 걸렸고, `/health`와 상세 API도 HTTP 200을 반환했습니다. 핵심은 계산만 한 것이 아니라 저장 후 같은 결과를 다시 읽었다는 점입니다.

## 4. 확인한 것과 아직 보장하지 못한 것 — 약 35초

**화면:** `4. 부하·장애·복구`와 `7. 남은 문제`

기존 시험에서는 Kafka 발행·수신·Spark 입력 일치, 거래소를 포함한 식별키 적용 후 중복 0건, PostgreSQL 장애 후 Upsert 복구를 확인했습니다. 파티션 최대 비중도 별도 시험에서 97.5%에서 33.9%로 낮췄습니다.

과거 Airflow의 `COMPLETE` 분류는 이전 coverage 계약의 기록이라 그대로 재사용하지 않았습니다. 9월 8일 현재 코드로 202회와 10종목을 다시 수집한 결과, session 요청 2,020건은 모두 정상 종료됐습니다. 실제 1분봉 품질은 COMPLETE 581건, PARTIAL 1,409건, 휴장으로 데이터가 없는 30건으로 따로 기록했습니다.

같은 원천으로 영향 분석 8,080행과 전략 2,020행도 다시 계산했고 중복은 0건이었습니다. 별도 Alpaca Paper 경로에서는 NVDA 1주 지정가 주문을 실제 모의계좌에 접수하고 취소해 `accepted → canceled`, 체결 0주와 DB 기록 1행을 확인했습니다. 다만 연구 신호가 자동으로 주문되지는 않습니다. 다음에는 발표 전망치와 비교군, 실제 모의체결 이후의 포지션 대사와 위험 한도를 검증하겠습니다. 감사합니다.

## 5. 웹 모의주문 화면 — 약 30초

**화면:** `http://127.0.0.1:8000/paper`

마지막으로 모의주문은 터미널 전용이 아니라 사이트에서 조작할 수 있습니다. Paper 계정과 장 시각을 확인하고, 종목·수량·지정가를 입력한 뒤 먼저 검토합니다. 이 단계에서는 증권사 요청을 보내지 않습니다.

실제 제출은 `SUBMIT PAPER ORDER`를 정확히 입력하고 서버의 Paper 주문 허용 설정도 켜져 있어야 합니다. 주문 목록에서는 상태를 다시 조회하거나 `CANCEL PAPER ORDER` 확인 후 취소할 수 있습니다. 이 화면은 Alpaca Paper만 사용하며 실계좌와 연구 신호 자동 주문은 지원하지 않습니다.

## 시간이 부족할 때 2분 버전

1번을 말한 뒤 데이터는 “202회·10종목·2,020개 조합”만 언급합니다. 바로 70초 영상을 재생하고, 종료 후 다음 문장으로 마칩니다.

> 저장 결과 조회와 전체 202×10 재수집·재계산을 완료했고, 별도 Alpaca Paper 수동 주문의 접수·취소도 검증했습니다. 연구 신호의 자동 주문과 실전 주문은 하지 않습니다. 감사합니다.

## 질문을 받았을 때 짧게 답하기

- **영상의 터미널 화면은 실제 실행인가요?** 실제 리허설 명령의 출력을 발표용 화면으로 정리한 캡처입니다. 실행 결과 원본은 최종 검증 JSON에도 보존했습니다.
- **한 번의 명령에서 무엇을 했나요?** 저장된 한 발표·한 종목을 입력으로 영향 4행과 전략 1행을 계산·Upsert하고, 같은 서빙 계층으로 결과와 1분·3분·5분봉을 재조회했습니다.
- **LONG인데 왜 자동 주문하지 않나요?** 과거 데이터로 만든 연구 신호이므로 자동 행동은 `NO_TRADE`입니다. 모의주문은 사용자가 사이트에서 종목·수량·지정가를 직접 입력하고 명시적으로 승인하는 별도 화면에서만 가능합니다.
- **모의주문은 실제로 가능한가요?** 네. Alpaca Paper 전용 계정에 NVDA 1주 지정가 주문을 접수·조회·취소했고 DB에 한 행만 기록되는 것을 확인했습니다. 실계좌 주문은 지원하지 않습니다.
- **180분과 181개 중 무엇이 맞나요?** 수집은 181개 후보 시각을 요청하고, 서빙 차트는 끝 시각을 제외한 180분을 표시합니다.
- **빈 분은 수집 실패인가요?** 아닙니다. 요청 완료 여부와 실제 가격 봉의 관측 밀도를 따로 기록합니다.
- **3분봉과 5분봉은 결측을 채웠나요?** 아닙니다. 실제 1분봉만 묶고 source count와 `PARTIAL`을 보존합니다.
- **202×10 상태도 새 계약으로 검증됐나요?** 네. 9월 8일 전체를 다시 수집해 provider collection과 실제 봉 품질을 분리 기록했습니다.
- **전체 전략 결과도 다시 계산했나요?** 네. 기존 90% 분석 규칙과 기존 전략 로직을 바꾸지 않고 영향 8,080행과 전략 2,020행을 재계산했습니다.
