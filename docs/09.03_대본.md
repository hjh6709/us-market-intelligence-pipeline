# 09.03 6차시 발표 대본

> 예상 시간: 약 4분
> 발표 화면: `docs/load-recovery-assignment.md`

## 1. 무엇을 보완했는가

**화면:** `먼저 보는 결론`과 전체 구성도

안녕하세요. 이번에는 기존 부하·복구 결과를 다시 설명하는 데 그치지 않고, 파이프라인의 이벤트와 종목 범위를 실제로 확장했습니다.

현재 흐름은 네 가지입니다. 첫째는 개별 체결을 Kafka와 Spark로 처리하는 원시 데이터 검증 경로입니다. 둘째는 경제 발표 전후의 1분봉과 일봉을 모으는 시장 데이터 경로입니다. 셋째는 발표 당시 알 수 있었던 FRED·ALFRED 경제지표를 연결하는 경로입니다. 넷째는 저장 결과로 이벤트 전후 반응과 단순 기준 전략을 계산하는 분석 경로입니다.

이 네 경로는 데이터 한 행의 의미가 다르기 때문에 건수를 섞지 않고 따로 설명하겠습니다.

## 2. 기존 부하·복구 결과

**화면:** `1. 기준 실행과 부하·복구 결과`

기존 부하 실험은 CPI 발표 55회와 네 종목의 실제 SIP 개별 체결 7,360,804건입니다. 외부 Alpaca API에 736만 건의 부하를 보낸 것이 아니라, 먼저 수집해 Parquet 파일로 보관한 원본을 Kafka에 재생했습니다.

Kafka 발행, 수신과 Spark 입력은 모두 7,360,804건이었고, 최종 1분봉은 22,260행이었습니다.

이전 결과에서 중복으로 표시했던 49건도 다시 확인했습니다. 실제 중복이 아니라 거래소가 다른 별개의 체결이었는데, 기존 식별키에 거래소가 빠져 같은 거래로 인식한 문제였습니다. 식별키에 거래소를 추가하고 전체를 다시 처리한 결과 실제 중복과 DB 중복은 모두 0건이었습니다.

## 3. 이번에 확장한 범위

**화면:** `2. 이번에 확장한 실제 데이터`

이번에는 공식 자료를 기준으로 2022년부터 2026년 8월까지 CPI 55회, 고용보고서 55회, PCE 55회, FOMC 37회, 총 202개 발표를 정리했습니다.

종목은 SPY, QQQ, IWM, TLT, XLF, SMH, GLD, NVDA, AAPL, JPM 열 개입니다. 따라서 202회 곱하기 10종목으로 2,020개 발표-종목 구간을 처리했습니다.

각 발표의 60분 전부터 120분 후까지 실제 존재하는 SIP 1분봉은 모두 308,512행이었습니다. 이 1분봉에서 3분봉 112,593행과 5분봉 70,090행을 만들었습니다. 발표일 전후 7거래일의 일봉 선택 합계는 30,250행입니다.

같은 202개 발표에는 FRED·ALFRED 경제지표 10개씩을 연결해 2,020개 context를 저장했습니다. 이 값은 전망치나 surprise가 아니라, 각 발표 당시 확인할 수 있었던 물가·고용·금리·VIX 환경입니다.

여기서 이 숫자는 이벤트별 선택 합계입니다. 가까운 날짜의 발표가 같은 거래일을 공유하면 PostgreSQL에는 같은 일봉을 한 번만 저장합니다. 그래서 이벤트별 합계와 DB 고유 행 수는 다를 수 있습니다.

1분봉이 구간마다 항상 181개인 것도 아닙니다. 8시 30분 발표는 장전이 포함돼 거래가 없던 분이 있을 수 있습니다. 없는 가격을 채우지 않고, 3분봉과 5분봉에 실제 포함된 1분 수와 COMPLETE 또는 PARTIAL 상태를 저장했습니다.

## 4. Kafka와 Airflow 개선

**화면:** `2.3 Kafka 파티션 개선`과 `4. Airflow 자동화`

기존 Kafka는 종목코드만 key로 사용해 한 파티션에 메시지의 97.5%가 몰렸습니다. 새 v2는 경제 이벤트, 발표일, 종목과 15분 구간을 key로 사용하고 파티션을 6개로 늘렸습니다.

같은 기준 데이터 118,118건을 실제 다시 실행한 결과, 발행·수신·Spark 입력이 모두 일치했고 가장 큰 파티션의 비중은 33.9%로 낮아졌습니다. 완전히 균등한 것은 아니지만 기존 쏠림은 크게 줄었습니다.

Airflow 시장 DAG도 종목마다 API를 호출하던 구조에서 경제 발표 한 건을 task 하나로 만들고, 그 안에서 10종목을 묶어 요청하도록 바꿨습니다. 이론상 요청 수는 4,040회에서 404회로 줄었습니다.

처음에는 FOMC 한 번과 SPY, TLT로 smoke test를 했고, 이후 같은 시장 DAG를 202개 발표 전체로 실행했습니다. 발표 하나가 task 하나이고, 각 task 안에서 10종목을 묶어 조회합니다. DB에는 발표와 종목별로 2,020개 작업 상태가 남고 마지막 검증 task가 누락과 미해결 alert를 확인합니다.

경제 맥락 DAG도 202개 발표 전체를 실행했습니다. 이미 저장한 발표 시점 값은 외부 API를 다시 호출하지 않고 재사용하고, 마지막에 2,020개 context가 모두 있는지 확인했습니다.

## 5. 분석 결과와 현재 경계

**화면:** `3. 장애 재현과 복구`, `5. 최신 데이터 모델과 남은 작업`

Spark는 736만 건의 중간 DataFrame을 RAM에 보관할 때 heap 부족이 발생했습니다. 그래서 반복 사용하는 중간 결과를 DISK_ONLY로 변경했고, 처리가 끝나면 unpersist로 해제하도록 했습니다.

DB 장애는 GCP VM 전체가 아니라 PostgreSQL 컨테이너만 중지해 재현했습니다. DB를 다시 시작한 뒤 실패한 입력을 재실행했고 Upsert 결과 22,260행과 중복 0건이 유지됐습니다.

API 장애는 외부 서비스가 아니라 로컬 mock의 첫 요청만 503으로 만들었습니다. 작업과 alert가 FAILED와 OPEN으로 기록됐고, 재시도 후 SUCCEEDED와 RESOLVED로 바뀌는 것을 확인했습니다.

최종 저장 결과가 실제 분석까지 이어지는지도 확인했습니다. 202개 발표, 10종목, 발표 전후 네 구간의 수익률·거래량·변동성을 계산해 8,080행을 저장했습니다.

아직 전망치와 surprise가 없기 때문에 경제지표 방향을 맞히는 전략은 만들지 않았습니다. 대신 발표 전 60분 가격 방향만 보고 같은 방향으로 진입해 발표 60분 뒤 청산하는 단순 기준을 실행했습니다. 왕복 비용 10bp를 차감한 1,988개 결과의 평균은 마이너스 0.1565%였고, 양수 비율은 39.34%였습니다. 즉 현재 규칙은 수익성이 없었습니다.

이 결과는 여러 종목을 합친 포트폴리오 수익률도 아니고 경제지표의 인과 효과도 아닙니다. 다음에는 신뢰할 수 있는 당시 전망치와 실제값, 비발표일 비교군, 호가 기반 슬리피지를 추가해야 합니다. 지금은 데이터 파이프라인의 저장 결과가 재현 가능한 분석과 실패한 전략 검증까지 연결됐다는 데 의미가 있습니다. 감사합니다.

## 질문을 받았을 때 짧게 답하기

- **736만 건과 30만 행의 차이는?** 736만 건은 개별 체결이고, 30만 행은 여러 발표 구간의 1분봉 선택 합계입니다.
- **왜 1분봉이 항상 181개가 아닌가?** 장전에는 실제 거래가 없던 분이 있으며, 가격을 임의로 채우지 않았기 때문입니다.
- **3분봉·5분봉으로 결측을 숨겼나?** 아닙니다. 실제 1분봉만 묶고 부족한 묶음은 PARTIAL로 표시했습니다.
- **FRED 값은 발표의 실제값인가?** 각 발표 당시 이용 가능했던 경제 환경입니다. 전망치·actual·surprise는 아직 별도 수집이 필요합니다.
- **전체 Airflow 실행을 했나?** 네. 시장·경제 맥락 DAG 모두 202개 발표 task 전체를 실행했고 최종 건수를 검증했습니다.
- **예상 수익률이 -0.1565%인가?** 아닙니다. 단순 규칙의 과거 발표-종목별 평균 결과이며, 미래 기대수익률이나 포트폴리오 수익률이 아닙니다.
