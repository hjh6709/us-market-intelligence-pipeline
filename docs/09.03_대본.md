# 09.03 6차시 발표 대본

> 예상 시간: 약 4분
> 발표 화면: `docs/load-recovery-assignment.md`

## 1. 결과 요약

**화면:** `먼저 보는 결론`

안녕하세요. 이번에는 기존 부하·복구 결과를 보완하고, 지금까지 만든 파이프라인이 실제로 어디까지 이어지는지 점검했습니다.

현재 두 경로가 있습니다. 첫 번째는 실제 원시 체결을 Parquet에서 읽어 Kafka, Spark, PostgreSQL로 보내는 검증 경로입니다. 두 번째는 공식 경제 발표를 기준으로 Alpaca의 분석용 1분봉과 일봉을 수집하는 경로입니다.

## 2. 부하와 복구

**화면:** `1. 정상 입력과 결과`, `2. 더 큰 입력과 실행 환경`

기준은 CPI 한 번과 네 종목의 SIP 체결 118,118건입니다. Kafka 발행·수신과 Spark 입력이 같았고 PostgreSQL에는 472개 1분봉을 저장했습니다.

이를 CPI 55회로 확대해 실제 체결 7,360,804건을 GCP에서 처리했습니다. Kafka 발행·수신·Spark 입력이 모두 일치했고, Spark는 원본의 동일 event ID 49건을 한 번만 남겼습니다. 최종 1분봉은 22,260행, DB 중복은 0건, 실행 시간은 약 28분 10초였습니다.

처음에는 Spark 중간 결과를 메모리에 두면서 Java heap 부족이 발생했습니다. 이를 `DISK_ONLY`로 바꾸고 같은 전체 입력을 다시 실행해 완료했습니다.

PostgreSQL 컨테이너를 중지했을 때는 DB 단계가 실패로 기록됐습니다. DB를 다시 시작하고 같은 입력부터 재실행한 뒤에도 최종 22,260행과 중복 0건이 유지됐습니다.

## 3. 77회·10종목과 Airflow

**화면:** `경제 이벤트·10종목 분석용 bar`, `실제 Airflow event-symbol 실행`

분석 데이터는 CPI, 고용, PCE, FOMC 77회와 10종목으로 넓혔습니다. 발표 전후 1분봉은 117,566행이고, 여기서 3분봉 43,184행과 5분봉 26,883행을 만들었습니다. 발표 전후 7거래일 일봉은 고유키 기준 8,740행입니다.

이번에는 이 코드를 Airflow에 실제 연결했습니다. 실행 단위는 경제발표 1건과 종목 1개입니다. 한 종목이 실패해도 작업을 구분할 수 있고, bar 전체가 아니라 식별자와 건수만 Airflow에서 전달합니다.

FOMC 2026년 7월 29일과 SPY, TLT로 실행했습니다. 종목마다 1분봉 181개, 3분봉 61개, 5분봉 37개와 일봉 15개가 저장됐습니다. 두 종목 합계는 588행입니다.

동일 입력을 재실행해도 588행과 결과 hash가 유지됐고 DB 중복은 0건이었습니다.

## 4. Alert와 남은 작업

**화면:** `API 503와 alert`, `현재 실제 연결과 남은 작업`

외부 API에 장애 요청을 보내지 않고 로컬 mock이 첫 요청에서 503을 반환하게 했습니다. 첫 시도에는 작업 실패와 alert OPEN이 기록됐고, 합성 fixture로 재시도한 뒤 성공과 RESOLVED로 바뀌었습니다. fixture는 장애 제어만 검증하며 시장 데이터로 사용하지 않습니다.

현재 수집, Kafka 전달, Spark 전처리, PostgreSQL 저장, Airflow 작업 분리, 재실행과 alert 상태까지 확인했습니다.

남은 것은 새 DAG으로 전체 770개 작업을 다시 실행하는 것, Kafka key와 파티션 수를 비교해 97.5% 쏠림을 개선하는 것, 다른 경제지표의 실제 발표값을 연결하는 것입니다. 이후 전체 영향 분석과 거래비용을 포함한 백테스트를 진행하겠습니다. 감사합니다.
