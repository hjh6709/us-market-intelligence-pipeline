# 1차시 발표 대본

예상 시간: 약 2분

안녕하세요. 제가 만들 프로젝트는 **미국 경제지표 발표가 주식시장에 어떤 반응을 만들었는지 검증하는 데이터 파이프라인**입니다.

장기적으로는 이 데이터를 자동매매 전략에 활용하고 싶습니다. 하지만 이번 4주 동안 바로 주문 기능을 만드는 것은 아닙니다. 먼저 매매 판단에 사용할 데이터가 믿을 만한지 확인하는 것이 목표입니다.

사용할 데이터는 크게 세 가지입니다.

첫째, BLS와 연준 같은 공식 사이트에서 CPI, 고용지표, FOMC의 정확한 발표 시각을 가져옵니다.

둘째, FRED와 ALFRED에서 발표된 경제지표 값과 그 당시 기준의 데이터를 가져옵니다. 나중에 수정된 값을 과거 분석에 잘못 사용하는 것을 막기 위해서입니다.

셋째, Alpaca에서 미국 주식과 ETF의 1분 가격·거래량 데이터를 가져옵니다. 약 22개 종목을 대상으로 하고, SPY와 QQQ 같은 시장 ETF와 반도체 ETF도 함께 봅니다.

분석 방법은 간단합니다. 경제지표 발표 전후 5분, 30분, 60분 동안 가격과 거래량, 변동성이 얼마나 바뀌었는지 계산합니다. 그리고 평소 같은 시간대, 전체 시장, 같은 업종 ETF와 비교합니다. 과거의 같은 발표도 여러 번 비교해서 비슷한 반응이 반복됐는지 확인합니다.

따라서 한 번 주가가 올랐다고 해서 “CPI 때문에 올랐다”고 단정하지 않습니다. 실제로 반복해서 관찰된 반응과 데이터가 부족한 부분을 함께 보여주는 것이 결과입니다.

또 무료 공식 데이터에서 시장 예상치를 구하지 못하면 “예상보다 높아서 올랐다”처럼 해석하지 않고, 발표 전후에 실제로 관찰된 반응까지만 말하겠습니다.

데이터 흐름은 **공식 발표 일정과 FRED, Alpaca 데이터를 수집하고, 가공한 뒤 PostgreSQL에 저장하는 구조**입니다.

Kafka는 실시간 거래 데이터를 안전하게 전달하고 잠시 보관하기 위해 사용합니다. Spark는 개별 거래를 1분 가격·거래량 데이터로 가공하고 이상 움직임을 찾는 데 사용합니다. Airflow는 경제지표와 과거 시장 데이터를 정해진 순서로 수집하고, 실패한 작업을 다시 실행하기 위해 사용합니다.

장이 닫혔거나 API를 사용할 수 없는 경우에는 실제 API 형식과 같은 테스트용 거래 데이터를 만들어 빠르게 재생합니다. 이 데이터는 시장 분석 결과에는 사용하지 않고, 파이프라인과 장애 복구를 테스트하는 데만 사용합니다.

최종적으로는 **어떤 경제지표가 언제 발표됐고, 그 전후에 각 종목이 평소와 비교해 어떻게 움직였는지 확인할 수 있는 결과**를 만들겠습니다. 이후 충분히 검증된 결과만 매매 전략과 백테스트로 이어가는 것이 장기 계획입니다.

## 예상 질문과 짧은 답변

### 왜 바로 자동매매를 만들지 않나요?

경제지표 발표와 주가 움직임이 동시에 일어났다는 이유만으로 바로 매매하면 위험합니다. 먼저 과거 여러 사례와 비교하고, 그다음 백테스트와 위험 관리를 거쳐야 합니다.

### FRED는 어디에 사용하나요?

경제지표 값과 과거 수정 이력을 가져오는 데 사용합니다. 정확한 장중 발표 시각은 BLS·BEA·연준의 공식 일정에서 따로 가져옵니다.

### Alpaca 데이터는 무엇에 사용하나요?

Historical SIP 1분 데이터는 경제지표 발표 전후의 전체시장 반응을 분석하는 데 사용합니다. 무료 실시간 IEX 데이터는 Kafka와 Spark 실시간 파이프라인 및 예비 이상 탐지에 사용합니다.

### 무엇을 비교하나요?

발표 전후 5분·30분·60분의 수익률, 거래량과 변동성을 평소 같은 시간대, SPY·QQQ, 섹터 ETF, 과거 동일 발표와 비교합니다.

### 경제지표가 원인이라고 증명할 수 있나요?

이번 프로젝트만으로 인과관계를 확정하지 않습니다. 공식 발표 시각을 기준으로 반복해서 관측된 연관성과 한계를 보여줍니다.

### 발표 값이 좋았는지 나빴는지도 판단하나요?

시장 예상치를 신뢰할 수 있는 출처에서 구한 경우에만 actual과 비교합니다. 예상치가 없으면 발표 전후 시장 반응만 분석하고 surprise를 임의로 만들지 않습니다.

### 왜 Kafka, Spark와 Airflow를 모두 사용하나요?

Kafka는 실시간 전달과 재처리, Spark는 거래 데이터의 1분 집계와 지연·중복 처리, Airflow는 공식 발표·FRED·과거 SIP 데이터의 예약 수집과 재실행을 담당합니다.

### 가짜 데이터도 분석에 사용하나요?

아닙니다. Replay 데이터는 데모와 부하·장애 테스트용입니다. 경제지표 결과는 공식 발표 정보와 실제 historical SIP 데이터로 계산합니다.
